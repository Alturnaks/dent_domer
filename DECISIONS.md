# DECISIONS

Одна строка на решение: `дата — область — решение — причина`.

- 2026-09-28 — лицензии — QuestPDF под Community License (бесплатна при годовой выручке < $1M); при превышении — купить лицензию или заменить — SPEC §2
- 2026-09-28 — лицензии — не используем AutoMapper, MediatR, FluentAssertions (коммерческие лицензии); вместо них ручной маппинг, сервисы-хендлеры, Shouldly — SPEC §2
- 2026-09-28 — окружение — помимо Makefile поддерживаем `scripts/dev.ps1` с теми же командами — разработка на Windows
- 2026-09-28 — seed — логины: owner, senior1-2, admin1-3, doctor1-6 @demo.kz, пароль demo12345 — нужны однозначные логины для check-roles
- 2026-09-28 — auth — тело логина `{login, password}`, форма ответа `/auth/me` и `GET /health` зафиксированы в SPEC §19 — под них написаны скрипты проверки
- 2026-09-28 — роли — таблица 5.4 переведена в исполняемую матрицу `scripts/roles-matrix.json`; спорные клетки таблицы трактованы так: старший админ без перемещений между филиалами и без управления ролями, кладовщик без доступа к кассе и расписанию, врач видит только своё расписание
- 2026-09-28 — dev — порты: web 3100, API 5100, воркер 5101, Postgres 55432, Redis 56379, Mailpit 58025 — порты 3000/5000/8000 заняты другими проектами у заказчика; весь стек поднимается в Docker (`start.bat`)
- 2026-09-28 — seed — в SPEC §15 указано «12 сотрудников», но перечислено 14 (1+2+3+1+1+6); созданы 14 по перечню
- 2026-09-28 — nuget — Newtonsoft.Json закреплён 13.0.4 (транзитивная уязвимая 11.0.1 от Hangfire), аудит NuGet только по прямым зависимостям
- 2026-09-28 — rls — RLS-политики навешиваются идемпотентно командой migrate на все таблицы с organization_id (DO-блок), а не вручную в каждой миграции: новая таблица не может «забыть» политику
- 2026-09-28 — rls — вход, фоновые задачи и seed-проверки читают глобальные связи через роль-владельца (SystemDb); таблицы users/refresh_tokens глобальные без RLS
- 2026-09-28 — api — Application ссылается на EF Core + Npgsql (ILike, DbSet в сервисах); запрет DbContext в эндпоинтах сохраняется
- 2026-09-28 — docker — по умолчанию start.bat поднимает всё в Docker (нужен только Docker Desktop); режим -Local для разработки
- 2026-09-28 — frontend — FullCalendar resource-плагины платные (Scheduler); в dev используется ключ CC-Attribution-NonCommercial-NoDerivatives, для продакшена нужна лицензия
- 2026-09-28 — роли — по решению заказчика роли «Кладовщик» и «Кассир» убраны; их права (склад, касса, возвраты, расходы) переданы администратору и старшему администратору; лимиты админа: скидка 5%, списание 50 000 ₸, возврат 20 000 ₸. Старая демо-БД с этими ролями пересоздаётся seed-ом автоматически
- 2026-09-28 — инфраструктура — MinIO и Seq вынесены в профиль `extras` (образ minio/minio больше не публикуется в Docker Hub)
- 2026-09-29 — auth — refresh_tokens исключена из RLS: обновление сессии выполняется до установки app.org_id (иначе F5 выкидывал на страницу входа)
- 2026-09-29 — EF — первичные ключи Guid помечены ValueGeneratedNever (Id задаётся в коде): иначе дочерние сущности, добавленные через навигацию, сохранялись как UPDATE → 409
- 2026-09-29 — расписание — согласованность: изменение графика, выходного/отпуска/больничного, блокировки, увольнение/смена филиалов врача, отключение кресла или филиала применяются в транзакции и проверяют будущие записи (ScheduleImpactService). Затронутые записи → 409 SCHEDULE_HAS_APPOINTMENTS со списком; пользователь выбирает: отменить + лист ожидания + сообщение пациенту (шаблон clinic_cancel) или оставить с уведомлением администраторам. В дни отсутствия врача запись невозможна даже с force
- 2026-09-29 — закупки — автозаявка: на склад одна открытая (draft/submitted) автозаявка; повторный запуск обновляет её строки, при отсутствии потребности — закрывает (rejected с комментарием); «уже заказано» учитывает неполученный остаток открытых заказов и открытые ручные заявки — чтобы не дублировать потребность
- 2026-09-29 — закупки — ночная задача запускается ежечасно (cron `5 * * * *`) и обрабатывает организации, где локальное время 03:xx — Hangfire не умеет cron в часовом поясе каждой организации
- 2026-09-29 — закупки — обработка части строк заявки переносит эти строки в новую заявку со статусом processed/rejected (исходная остаётся submitted) — ничего не удаляем, статус заявки однозначен
- 2026-09-29 — закупки — порог подтверждения заказа берётся из настроек организации (`purchase_order_approval_threshold`, по умолчанию 500 000 ₸); подтверждение запрашивается при отправке заказа; одобрение → sent, отклонение → снова черновик
- 2026-09-29 — закупки — приход по заказу поставщику всегда создаёт счёт поставщика (номер — номер накладной или прихода); сторно прихода списывает неоплаченный остаток счёта в returned_amount
- 2026-09-29 — закупки — сводная потребность и обработка доступны правам purchase.order.create/approve (админ сети); филиал с purchase.request.create видит и отправляет только заявки своих филиалов; перемещение с центрального требует ещё inventory.transfer.create
- 2026-09-29 — экспорт — табличные документы (заказ поставщику) рендерятся через ITableDocumentRenderer: Excel — ClosedXML, PDF — QuestPDF; текстовый вариант для WhatsApp/почты и CSV — без библиотек
- 2026-09-29 — зарплата — визит попадает в период по дате закрытия в часовом поясе организации; выручка врача = сумма visit_items.total его позиций (позиция может принадлежать другому врачу), материалы — себестоимость visit_material_usage его позиций (без привязки к позиции — врачу визита); «только оплаченные» = paid_total ≥ total (настройка PayrollOnlyPaidVisits)
- 2026-09-29 — зарплата — схема: действующая на конец периода (последняя версия с valid_from ≤ period_end); смена схемы = новая версия, старые не меняются (с той же датой — уточняется). Оклад fixed_plus_percent начисляется целиком за ведомость; смены per_shift = дни с закрытыми визитами врача (график не используется: он показывает план, а не факт)
- 2026-09-29 — зарплата — ведомости одного филиала не пересекаются (409 PAYROLL_PERIOD_OVERLAP); пересчёт только в draft и сохраняет бонусы/штрафы; строки врачей не удаляются (выпавшие обнуляются); бонус/штраф требует комментарий и пишется в аудит (payroll_adjust). Изменение визита в утверждённой ведомости → approval PayrollPeriodChange; утверждённая ведомость при этом не пересчитывается
- 2026-09-29 — подозрительные события — «новое устройство» = новый хэш User-Agent в user_devices; самое первое устройство пользователя — точка отсчёта (не помечается). «Вне рабочего времени» — вне часов всех филиалов сотрудника (без филиалов — часы организации по умолчанию). В audit_log событие без user_id (вход до аутентификации), пользователь — в diff
- 2026-09-29 — тесты — `global.json` в корне: `test.runner = Microsoft.Testing.Platform` (xunit.v3 на .NET 10 SDK не запускается через VSTest-таргет); запуск — `dotnet test --project <путь>`
- 2026-09-29 — seed — демо-врачам создаются схемы оплаты всех 4 типов с 1 января текущего года, чтобы ведомость считалась сразу
