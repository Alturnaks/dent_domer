# Файлы и резервные копии ABP

Карточка пациента хранит метаданные файлов в PostgreSQL, содержимое — в закрытом S3-совместимом бакете `dental-files`. Поддерживаются PDF, PNG и JPEG до 20 МБ. Доступ использует существующие права `Patients.View` и `Patients.Edit` и фильтр организации. При слиянии карточек метаданные переводятся в основную карточку; ключ объекта остаётся стабильным.

Загрузка идёт напрямую в S3 по подписанной POST-политике AWS Signature V4 на 10 минут. Политика фиксирует ключ, MIME и точный размер. После загрузки сервер сверяет размер, MIME и сигнатуру содержимого; копирует проверенный ETag из `pending/` в постоянный ключ. Ссылка загрузки не позволяет менять постоянный файл. Скачивание выдаёт ссылку на 5 минут с принудительным сохранением, а не исполнением содержимого в приложении. Проверка сигнатуры не заменяет антивирусную проверку. Мягкое удаление скрывает файл и запрещает выдачу новых ссылок; уже выданная ссылка действует до истечения срока.

`abp/docker-compose.yml` создаёт MinIO, закрытые бакеты `dental-files` и `dental-backups` и очистку временных объектов `pending/` через один день. Версии MinIO и mc фиксированы в `abp/docker/Storage.Dockerfile` и собираются из официального исходного кода. Порты хоста привязаны к loopback: S3 — 59002, консоль — 59003. Данные находятся в отдельном Docker volume `abp_minio`.

Исходные версии: [MinIO RELEASE.2025-10-15T17-29-55Z](https://github.com/minio/minio/tree/RELEASE.2025-10-15T17-29-55Z) и [mc RELEASE.2025-08-13T08-35-41Z](https://github.com/minio/mc/tree/RELEASE.2025-08-13T08-35-41Z). Тексты лицензий включены в образы. Формат политики соответствует [AWS POST Policy](https://docs.aws.amazon.com/AmazonS3/latest/developerguide/sigv4-HTTPPOSTConstructPolicy.html).

## Конфигурация

Приложение принимает `Storage__ServiceUrl` (адрес внутри Docker), `Storage__PublicUrl` (адрес для клиента), `Storage__AccessKey`, `Storage__SecretKey`, `Storage__Region`, `Storage__Bucket`. Для внешнего S3 нужны HTTPS-адреса, закрытый бакет, CORS для точного адреса приложения и сервисный ключ с доступом только к файловому бакету. Временные AWS STS credentials пока не поддерживаются. В локальном compose используются демонстрационные значения; рабочие ключи задаются через окружение, а не коммитятся. `ABP_MINIO_USER`, `ABP_MINIO_PASSWORD` определяют локальные учётные данные; `ABP_WEB_PORT` задаёт origin CORS.

## Резервные копии

```powershell
./scripts/backup-abp.ps1 -S3 -Keep 10
```

Скрипт создаёт `pg_dump -Fc`, проверяет архив через `pg_restore --list`, сохраняет локальную копию и отправляет в `dental-backups/postgres/dental_abp/`. Затем скачивает объект обратно и сравнивает SHA-256. Только после успешной проверки выполняется ротация. Удаляются исключительно архивы с точным шаблоном имени в заданном префиксе; остальные объекты не затрагиваются. По умолчанию сохраняются 10 последних копий локально и в S3. Без `-S3` остаётся прежняя локальная резервная копия.

Параметры `-S3Endpoint`, `-S3Bucket`, `-S3Prefix`, `-Network` позволяют указать другой S3-совместимый сервис. Секреты передаются через окружение контейнера mc и не включаются в аргументы команд. При ошибке S3 локальный архив остаётся, ротация не запускается. Поддерживаются постоянные ключи MinIO/S3 через `ABP_MINIO_USER` и `ABP_MINIO_PASSWORD`.

Резервная копия PostgreSQL содержит метаданные файлов, но не содержимое файлового бакета. Для полноценного аварийного восстановления требуется отдельно защищать файловое хранилище, например репликацией или резервированием его volume. Копия базы в MinIO на том же компьютере помогает восстановиться после ошибок приложения, но не защищает от потери самого компьютера.

Автоматическое расписание бэкапов пока не настроено: скрипт запускается вручную или внешним планировщиком. Восстанавливать архив сначала следует в отдельную временную БД, не поверх рабочей базы.
